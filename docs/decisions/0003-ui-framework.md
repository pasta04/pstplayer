# ADR-0003: フロントエンド UI フレームワーク選定

- **ステータス**: 採用 (2026-05-30) — **Svelte 5 + TypeScript + Vite**
- **決定者**: pasta04 (リポジトリオーナー)

## 背景

Tauri + Rust + Web UI 構成のフロントエンド側で、どの UI フレームワーク (Vue / React / Svelte / Solid 等) を採用するかを決める必要がある。

PSTPlayer のフロント要件:

- 動画表示エリア (libmpv のネイティブウィンドウ重畳。React/Vue 等の影響を受けにくい)
- BBS サブペイン (長いリストの仮想スクロール、自動更新時の差分描画)
- 設定ダイアログ群 (フォーム UI)
- ホットキー処理
- ダーク/ライトテーマ
- (将来) 多言語化

## 候補

| フレームワーク | バンドルサイズ | 学習コスト       | エコシステム            | Tauri 公式テンプレート |
| -------------- | -------------- | ---------------- | ----------------------- | ---------------------- |
| Svelte (Kit)   | 小             | 低               | 中                      | あり                   |
| React          | 中             | 中               | 最大                    | あり                   |
| Vue 3          | 中             | 低 (作者が慣れ?) | 大                      | あり                   |
| Solid          | 最小           | 中               | 小                      | あり                   |

## 検討ポイント

- **Tauri WebView のサイズ・速度**: Edge WebView2 (Win)、WebKit (Mac)、WebKitGTK (Linux) は概ね現代的だが、Linux の WebKitGTK は微妙にバグが多い。**バンドルサイズが小さく速いフレームワークが有利**
- **動画オーバーレイの相性**: libmpv の native window は DOM 外で描画されるが、CSS による位置調整は必要。どのフレームワークでも対応可
- **長いレス一覧のレンダリング性能**: 1 スレ 1000 レス想定。React なら `react-window`、Svelte なら `svelte-virtual-list`、Solid は `solid-virtual` など。仮想スクロールの選択肢があるか確認
- **状態管理**: Tauri event → ストアへの反映が容易か。Svelte の store、React の Zustand/Redux、Solid signal などで対応可
- **作者の慣れ**: 開発速度に直結

## 暫定推奨

**Svelte 5 (+ SvelteKit を SSR なしモードで)** を第一候補にしたい。理由:

1. バンドルサイズが小さく、Tauri の軽量性と相性が良い
2. Runes (Svelte 5) で状態管理が直感的
3. テンプレート構文が HTML に近く、シンプル
4. Tauri 公式に Svelte テンプレートあり

**次点で React (+ Vite)**:

- エコシステムが圧倒的に大きく、つまずいた時の情報量が多い
- 仮想スクロール、フォーム、i18n の枯れた選択肢が豊富
- ただし Svelte より初期セットアップとボイラープレートが多い

## 決定

**Svelte 5 + TypeScript + Vite** を採用。

理由 (暫定推奨で挙げた通り):

1. バンドルサイズが小さく、Tauri の軽量性と相性が良い
2. Runes (Svelte 5) で状態管理が直感的、外部ストアライブラリ不要
3. テンプレート構文が HTML に近く、シンプル
4. Tauri 公式テンプレート (`svelte-ts`) が利用可能

## 周辺技術 (フェーズ 1 で確定)

| 項目                  | 採用                                  | 備考                                          |
| --------------------- | ------------------------------------- | --------------------------------------------- |
| ビルドツール          | Vite                                  | Svelte テンプレート同梱                       |
| スタイリング          | vanilla CSS + CSS Variables           | Tailwind 等の上積みは見送り (フェーズ 2 で再検討) |
| 状態管理              | Svelte 5 Runes + stores               | 外部ライブラリ不要                            |
| ルーティング          | なし (シングルウィンドウ前提)         | サブウィンドウは Tauri マルチウィンドウ機能で  |
| i18n                  | フェーズ 4 で検討                     | MVP は日本語のみ                              |
| 仮想スクロール        | `svelte-virtual` 系 (フェーズ 2 で導入) | レス一覧 1000 件超対応用                      |

## 切り替えの可能性

採用後に致命的な問題が出たら React に切り替え可能 (バックエンドの Rust モジュールは UI フレームワークに依存しないため、フロント側のみ書き換え)。判断ポイント:

- libmpv のネイティブウィンドウ重畳が Svelte 側のレンダリングと干渉するケース
- 仮想スクロール ライブラリの品質が不足するケース
- 開発生産性が大幅に下回るケース
